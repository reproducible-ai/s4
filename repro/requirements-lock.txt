# Reproduction pin set for this row -- NOT an upstream file.
#
# Upstream's requirements.txt is unpinned apart from pytorch-lightning==2.0.4 and
# timm==0.5.4, and its last push was 2024-07. Three things force exact pins on a
# 2026 host:
#
#   torchtext  src/dataloaders/__init__.py imports lra.py, which imports torchtext
#              at module level. torchtext's final release (0.18.0) ships
#              libtorchtext.so linked against libtorch 2.3; on torch 2.7.0 it dies
#              with `undefined symbol: _ZN5torch6detail10class_baseC2ERKSsS3_...`.
#              That single unavoidable import pins the entire torch stack to 2.3.0.
#   numpy      torch 2.3.0 is built against numpy 1.x, and scipy >= 1.14 has
#              dropped the np.long alias that numpy 1.26 still exposes, so scipy
#              is pinned alongside it.
#   rich       pytorch-lightning 2.0.4's RichProgressBar calls
#              Console.clear_live() unconditionally; rich >= 14 keeps a live STACK
#              and raises `IndexError: pop from empty list`. rich 13.x is required.
#   setuptools pytorch-lightning 2.0.4 / lightning_fabric call
#              pkg_resources.declare_namespace(); setuptools >= 81 has removed
#              pkg_resources entirely.
#
# Every pin is a plain PyPI version. No local `+cuXXX` versions.
